## 30초 요약

**문제**: 기존 통합은 HA 프론트엔드의 minify 된 웹팩 번들(`site-packages/hass_frontend/**/*.js`)을
정규식으로 덮어써서 CARTO 타일 URL 을 네이버 타일 URL 로 바꿨다. 이 방식은
(a) HA 업데이트마다 소멸하고, (b) **HA 2026.9 에서 지도가 MapLibre + OSM 벡터 타일로 교체되어
치환 대상 문자열 자체가 사라졌으므로 이미 완전히 동작하지 않는다.**

**해법**: 파일을 고치지 않는다. 대신 세 조각을 만든다.
1. **타일 프록시 뷰** — `/api/map_tiles/naver_map_change/{z}/{x}/{y}.png`.
   서버가 upstream 타일을 받아 캐시해 브라우저에 전달한다.
2. **스타일 엔드포인트** — `/api/map_tiles/naver_map_change/style/{light|dark}.json`.
   MapLibre 래스터 스타일 JSON 을 서버가 생성한다(비밀값 없음).
3. **주입 JS 30줄** — 코어가 `/static/map/light.json` 을 fetch 할 때 위 엔드포인트로 갈아끼운다.
   그 외에는 아무것도 하지 않는다.

전부 `/config/custom_components/naver_map_change/` 안에 있으므로 **HA 업데이트와 무관하게 영속**한다.

**왜 서버측 프록시가 필수인가**: 2026.9 의 MapLibre 는 타일을 워커에서 `fetch` 로 받는다.
`map.pstatic.net` 은 CORS 헤더를 주지 않으므로 브라우저 직접 호출이 불가능하다. 또 `Referer`/
`User-Agent` 는 브라우저가 설정할 수 없는 forbidden header 다. 코어의 `map_tiles` 통합도 정확히
같은 이유로 프록시를 만들었다(그 docstring 이 근거로 인용되어 있다).

**설계의 열쇠**: 코어 프론트엔드의 `withMapTilesToken()` 은 pathname 이 `/api/map_tiles/` 로
시작하는 **모든** URL 에 유효한 회전 토큰을 붙인다. 우리 뷰를 그 하위에 두면 토큰 발급 체계를
직접 만들 필요가 없다. (이 사실은 원본 소스 fetch 로 직접 검증됐다 — `02` 문서 §3.3)

## 하드 제약 — 위반하면 구현 반려

1. `/config` 밖에 **쓰지 않는다.** `site-packages` / `hass_frontend` 에 대한 쓰기·백업·압축·삭제
   코드를 일절 작성하지 않는다.
2. `brotli` / `gzip` 재압축 코드를 만들지 않는다. `requirements` 는 빈 배열.
3. **실패는 기본 지도로 폴백한다.** 주입 JS 의 모든 경로를 `try/catch` 로 감싼다.
   지도가 백지가 되는 실패는 허용하지 않는다.
4. 이벤트 루프에서 blocking I/O 금지. HTTP 는 `async_get_clientsession()`, `urllib` 금지.
5. 최소 지원 버전 **HA 2026.9.0**. 그 이전은 지도 구조가 달라 이 설계가 성립하지 않는다.
6. `strings.json` 금지(코어 전용). 번역은 `translations/{en,ko}.json`.
7. **문서화되지 않은 값을 추측해서 코드에 넣지 않는다.** 네이버 타일의 헤더·타일크기·최대줌은
   `curl` 로 실측해 `05-UPSTREAM-FINDINGS.md` 에 근거를 남기고 나서 상수로 확정한다.
8. `03-REDESIGN-SPEC.md` §7 의 "이식 금지 목록"에 있는 함수·상수를 되살리지 않는다.

## 사용자가 확정한 방침

- **공식/공개 API 로 제한하지 않는다.** 비공식 엔드포인트(`map.pstatic.net`) 사용을 허용한다.
  따라서 `naver` provider 를 기본값으로 채택한다.
- 단, 약관·차단 리스크는 사실로 존재하므로 **provider 교체 가능 구조**와 **고지 문구**를 함께
  구현한다. 리스크를 이유로 구현을 거부하거나 축소하지 않는다. (`04` 문서 §3, §7)

## 신뢰도 표기 규약

문서 안의 표기를 그대로 신뢰 수준으로 받아들인다.

- **[직접검증]** — 원본 소스/문서를 fetch 해 확인함. 코드에 그대로 반영해도 된다.
- **[조사]** — 웹 근거와 함께 보고됐으나 원본 재확인은 안 됨. 구현 전 한 번 확인하는 것이 좋다.
- **[미확인]** — 근거 부족. **이 값을 코드에 하드코딩하지 말고 실측하거나 질문한다.**
